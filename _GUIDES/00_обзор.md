# Обзор: где что лежит и как всё соединяется

> Переписано под текущий РТС-каркас: контент готовых фракций вырезан, юниты/здания/фракции —
> **data-driven** (датапак JSON). Полная точка входа — `docs/HANDOFF.md`.

Пакет-корень: `src/main/java/com/solegendary/reignofnether/`. Пути ниже относительно него.

## Два рода реестров

* **Кодовые** (`api/ReignOfNetherRegistries`): `BUILDING`, `PRODUCTION_ITEM`, `DATA_TYPE` —
  наполняются статикой (`Buildings.init()`, `ProductionItems.init()`). `BUILDING` в этом каркасе
  **пуст** (здания — датапак).
* **Датапак-реестры** (регистрируются в `ReignOfNether#loadDatapacks`, синхронизируются клиентам):
  * `rts_buttons` — `CustomButtonServerEvents.CUSTOM_BUTTON_REGISTRY_KEY`;
  * `faction` — `FactionRegistries.FACTION_KEY`;
  * `unit` — `UnitDefinitions.UNIT_KEY` (`data/<ns>/unit/<name>.json`);
  * `building` — `BuildingDefinitions.BUILDING_KEY` (`data/<ns>/building/<name>.json`).

Reload-listener'ы (`ReignOfNether#reloadListener`): `CustomButtonMappingManager`,
`ResearchJsonLoader` (`data/<ns>/research/<name>.json`).
Отдельные реестры времени выполнения: `AbilityTypes` (способности, движковая регистрация),
`AddonTypes` (аддоны), `JsonBuildingManager` (варианты зданий по уровням).

## Порядок инициализации

`ReignOfNether.java` — конструктор мода. Порядок важен: реестры должны существовать до наполнения.

```java
EnchantmentRegistrar / AttributeRegistrar / ItemRegistrar / EntityRegistrar / ContainerRegistrar /
SoundRegistrar / BlockRegistrar / BlockEntityRegistrar;
GameRuleRegistrar.init();
Buildings.init();        // кодовые здания (в каркасе пусто)
Addons.init();           // движковые типы аддонов -> AddonTypes
ProductionItems.init();  // кодовые предметы производства
MobEffectRegistrar / ParticleRegistrar / CommandArgumentRegistrar / CustomButtonActions;
BuildingSelectorOptions.bootStrap(); ResourceObjectiveCriteria.init();
```

`loadDatapacks(DataPackRegistryEvent.NewRegistry)` — регистрация датапак-реестров.
`reloadListener(AddReloadListenerEvent)` — загрузчики JSON (`/reload`).
`FactionServerEvents.onServerStarted` — `JsonBuildingManager.reload(server)` строит варианты зданий.

## Data-driven контент

* **Юнит** = `base` (ванильный моб) + `data/<ns>/unit/<name>.json` (`UnitDefinition`). `role`/`flags`
  → goals (`UnitMobMixin.initialiseGoals`), `attributes`/`scale` → `UnitDefinitionRuntime`,
  `equipment` — предмет в руку, `projectile` — снаряд ranged-юнита. Способности — `AbilitySpec`
  (`type` → `AbilityTypes`, нужны зарегистрированные типы).
* **Здание** = `structure` (NBT) + `data/<ns>/building/<name>.json` (`BuildingDefinition`) →
  `JsonBuilding`. `production`/`researches` → очередь здания; `addons` → `AddonTypes`;
  `upgrades` → варианты уровней (`JsonBuildingManager`); `flags` → поведение (`BuildingDefinition.Flags`).
* **Фракция** — `data/<ns>/faction/<name>.json` (реестр `faction`), `/startrts [<faction>]`.

## Три шва, где всё сходится

1. **Юнит → производство.** `ProductionItem` (стоимость, `onComplete`) кладётся в очередь
   `ProductionPlacement`; JSON-здания дают `JsonProductionItem` (юнит по id определения),
   `ResearchProductionItem` (исследование) и `JsonUpgradeProductionItem` (апгрейд уровня).
2. **Здание → армия/население.** `Building.populationSupply` даёт прирост лимита (база — 1);
   у JSON-здания — из `populationSupply` определения.
3. **Гейты.** `Ability.requiredResearch`, `ProductionItem.requiredResearch`, `Building.requiredResearch`
   (`ResearchCondition`, с инверсией) — серверные проверки + HUD.
