# Обзор: где что лежит и как всё соединяется

> **Требует ревизии (2026-10-08).** Написан до вырезания контента: слои ниже упоминают удалённые
> подсистемы (чары, туман, режимы, faction-реестры) и старые счётчики. Актуальная карта — по
> `docs/STATUS.md` и коду; правки — совместно с владельцем.

Пакет-корень: `src/main/java/com/solegendary/reignofnether/`. Пути ниже относительно него.

## Порядок инициализации

`ReignOfNether.java:56-104` — конструктор мода. Порядок важен: реестры должны существовать
до того, как начнут наполняться статические поля.

```java
ItemRegistrar.init(container);
EntityRegistrar.init(container);
BlockRegistrar.init(container);
BlockEntityRegistrar.init(container);
GameRuleRegistrar.init();
Buildings.init();          // статические поля зданий -> реестр BUILDING
ProductionItems.init();    // стаические поля предметов -> реестр PRODUCTION_ITEM
```

`modBus.addListener(ReignOfNether::init)` вызывает `ResourceCosts.deferredLoadResourceCosts()`
на `FMLCommonSetupEvent`. **Значения стоимостей читать раньше CommonSetup нельзя** — будет
`IllegalStateException` (комментарий в `resources/ResourceCosts.java`).

## Три точки, где всё сходится

Юниты и здания связаны ровно в трёх местах — их нужно знать при любой правке:

1. **`ProductionItem` / `ProductionPlacement`** — единственный путь получить юнита. Список
   производств живёт на здании (`this.productions.add(...)` в конструкторе), очередь — на
   размещении.
2. **Лимит армии** — базовое значение 1, прирост даёт ратуша (после этапа E.4 плана).
3. **`GarrisonableBuildingAddon`** — здание как цель атаки и место гарнизона.

## Классы-регистраторы

Всё новое, что видно игре, регистрируется в `registrars/`. Паттерн один:

```java
public static final DeferredRegister<EntityType<?>> ENTITIES =
        DeferredRegister.create(BuiltInRegistries.ENTITY_TYPE, ReignOfNether.MOD_ID);

public static final Supplier<EntityType<XUnit>> X_UNIT = ENTITIES.register("x_unit",
        () -> EntityType.Builder.of(XUnit::new, MobCategory.CREATURE)
                .sized(width, height)
                .clientTrackingRange(100)
                .build(ResourceLocation.fromNamespaceAndPath(MOD_ID, "x_unit").toString()));
```

Атрибуты сущности **не** передаются в билдер. Их задаёт сам класс через
`public static AttributeSupplier.Builder createAttributes()`, начинающийся с
`Unit.createDefaultAttributes()` (`unit/interfaces/Unit.java`).

## Что проверять после правки

```
gradlew.bat compileJava      # 0 ошибок
gradlew.bat validateMixins   # 0 ошибок
gradlew.bat runData
gradlew.bat runServer        # завершается сам
gradlew.bat runClient        # НЕ завершается сам, останавливать вручную
```

Ни один гейт не проверяет геометрию на экране и не проверяет зависание при выходе из мира.
Туман войны удалён целиком (этап B.3), чары удалены (этап E.1) — это меняет набор проверок
на клиенте: искать исчезновение тумана не нужно, нужно искать, что рендерится лишнее.
