# Производство

> Это **каркас**, а не удалённый контент: `building/production/**` после этапа D остался целиком.
> Удалены только конкретные `*Prod`-элементы юнитов, они перечислены в `units.md`.

## Что осталось

| Класс | Роль |
|---|---|
| `ProductionItem` | один элемент обучения: имя, стоимость, `getEntityType()`, `tick()`, `onComplete` |
| `ActiveProduction` | элемент очереди на конкретном здании: `ticksLeft`, прогресс |
| `ProductionItemList` | список элементов с ключами и правилами дублирования |
| `ProdDupeRule` | можно ли строить/учить это повторно |
| `ProductionBuilding` / `ProductionPlacement` | здание, у которого есть очередь |

## Как это работает

* `ProductionItem` — самодостаточная единица: стоимость живёт **на нём** (`ResourceCost`), а не в
  списке юнитов по enum'у (решение 12.3). Поэтому `ReignOfNetherCommonConfigs` сведён к пустому
  spec, а 154 записи стоимостей удалены.
* Сопоставление с юнитом — прямое, по `EntityType<?>` (`ProductionItem.getEntityType()`), а не по
  строковому имени (решение 12.6, этап E.9). Раньше строка `itemName` обязана была совпадать со
  `case` в `EntityRegistrar.getEntityType`, иначе обучение в кастомных строениях молча ломалось.
* Лимит армии: базовый — `DEFAULT_MAX_POPULATION = 1`; прирост даёт ратуша
  (`Building.populationSupply`, сейчас только `TownCentre` = 10).
* `ProductionItem.tick` прогоняется и на клиенте и на сервере (клиент — для плавного прогресса).
