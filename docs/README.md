## Задача ветки `1.21.1-clean`

Цель: **чистый каркас РТС-системы.** Механика сохраняется (интерфейсы юнитов и зданий, цели,
производство, гарнизоны, ауры, атрибуты, эффекты, камера, HUD, команды, кастомные
строения). Контент готовых фракций удаляется, остаётся будущая фракция владельца ветки.
Читы и песочница удалены (в каркасе нет ни чит-переключателей, ни ГМ-инструментов спавна).

Принятые решения (не переоткрываются):

1. **Удаляются «дефолтные фракции» жителей / нежити / пиглинов** вместе со всем контентом —
   юниты, здания, способности, исследования, предметы, ресурсы, волны.
2. Удалённый контент сохраняется как **документация** в `docs/reference/`, не в дереве кода.
3. Режимы, кроме `CLASSIC`, удаляются.
4. `Faction` **удаляется**, абстракцией не заменяется.
5. Интрузивность убирается.

**⚠ После этапа D мод содержит ноль юнитов и ноль зданий** — гейты проходят, но в игре делать
нечего. Поэтому порядок важен: сначала A–C (интрузивность и режимы) — их ещё можно проверить
в игре, — и только потом D–F. Если нужен играбельный вариант, его стоит держать на отдельной
ветке от этапа C.

Три шва между юнитами и строениями описаны в `FEATURES.md` §1; применительно к этому плану
важно, что шов производства **сохраняется**, поэтому `ProductionItem` и
`ProductionPlacement` остаются, а `cost.population` требует плоского лимита (этап E.4).

Состояние самого порта лежит **вне git**, в корне репозитория (`ReignOfNether/`):
`AGENT_HANDOFF.md`, `AGENT_MEMO.md`, `AGENT_MEMO_merge_upstream.md`, `PORT_STATUS.md`,
`PORT_ANALYSIS.md`. Каталог `___temp/` — единственный git-репозиторий, и именно в нём живут
эти документы.

## Быстрый старт

`gradlew.bat` **не работает**: он передаёт java одновременно `-classpath ""` и `-jar`. Запускать
через java напрямую:

```bash
cd ___temp
JAVA="/c/Program Files/Java/jdk-21/bin/java.exe"
"$JAVA" -Dorg.gradle.appname=gradlew -jar gradle/wrapper/gradle-wrapper.jar <task> --offline --console=plain
# задачи-гейты: compileJava · validateMixins · runData · runServer (завершается сам) · runClient
```

Ни один гейт не проверяет геометрию на экране и не проверяет зависание при выходе из мира —
это только ручной прогон в игре.

## Правила работы с кодом этого мода

1. **Сверяться с апстримом.** `git show 918672b7:<путь>` — база 1.20.1; расхождение с ней
   часто и есть баг, но не всегда: часть отличий намеренная (см. §10 `AGENT_HANDOFF.md`).
2. **Симптом «не зависит от камеры» означает испорченные данные**, а не матрицы.
3. **Идентичные числа пробы между прогонами** означают, что состояние приходит из мира или
   конфигурации, а не накапливается в игре.
4. **`jstack` на зависшем процессе** быстрее любого чтения кода: сразу видно дедлок это или
   спин, и точную строку ванильного цикла.
5. **`javap` по `build/moddev/artifacts/neoforge-21.1.250-merged.jar`** — источник истины по
   сигнатурам 1.21.1; исходники ванилы распаковываются из
   `build/moddev/artifacts/neoforge-21.1.250-sources.jar` (в отличие от старых версий, там
   **есть** и `net/minecraft/**`).
6. Никаких «автофиксов» при переезде версии, молча меняющих числа: удалённый конструктор или
   метод заменять эквивалентом с проверенной семантикой, а не ближайшим по сигнатуре.
