# Переводы строк (CRLF-ловушка)

Репозиторий `___temp/` хранит **CRLF в большинстве `.java`** и CRLF в части `lang/*.json`.
`.gitattributes` их не нормализует, `core.autocrlf=false`.

**Симптом:** одна правка на 3 строки даёт дифф на весь файл (например 1868/1977 строк).
Причина: инструмент (обычно `sed -i`, реже `perl -i -pe 's/\r\n/\n/'`) переписал CRLF→LF.

**Как проверить:**

```bash
# cr == lines  → файл целиком CRLF
f=path/to/File.java; echo "cr=$(tr -cd '\r' < "$f" | wc -c) lines=$(wc -l < "$f")"
git diff --numstat -- "$f"           # если added ≈ lines, дифф — это смена окончаний
```

## Безопасная правка CRLF-файла

```bash
perl -i -pe 's/\r\n/\n/g' "$f"        # 1. в LF
# 2. править инструментом (str_replace, editor)
perl -i -pe 's/\r?\n$/\r\n/' "$f"     # 3. вернуть CRLF (идемпотентно)
```

Смешанные окончания (часть CRLF, часть LF) восстанавливать построчно бессмысленно — выровняй
файл по стилю из `HEAD` и не трогай остальное.

## Перед коммитом

```
git diff --numstat | sort -k2 -n | tail
```
Файл с числом удалённых строк ≈ размеру файла в `HEAD` и добавленных ≈ размеру файла на диске —
это смена окончаний. Такой коммит не делать: вернуть окончания и перепроверить.

**Ловушка-спутник:** `git show <ref>:<path> > out` под PowerShell 5.1 пишет UTF-16LE → javac
сыпет `unmappable character (0xFF)`. Использовать `cmd /c "git show ... > out"`.
